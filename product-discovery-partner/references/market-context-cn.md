# 中国市场上下文

这是一个可选模块。只有当产品面向中国大陆用户、涉及中国平台/支付/数据/内容，或用户主动要求时启用。

法规和平台规则会变化，必须查官方最新信息。本文件不构成法律意见。

## 1. 先问清楚

- 目标市场是中国大陆、港澳台、海外，还是混合？
- 用户主要从哪里进入：微信、抖音、小红书、应用商店、Web、线下？
- 是否面向消费者、企业、政府/国企、学校、医院？
- 是否涉及支付、发票、订阅、预付？
- 是否收集个人信息、敏感数据或未成年人数据？
- 是否涉及内容生成、社区、直播、电商、金融、医疗、教育？
- 团队是否有中国合规和运营经验？

## 2. 平台入口

| 平台 | 适合 | 主要限制 |
|---|---|---|
| 微信小程序 | 轻量工具、服务预约、会员、线下场景 | 审核、类目限制、支付/资质、无法自由跳转 |
| 微信公众号/服务号 | 内容、通知、客服、私域 | 模板消息限制、内容审核 |
| 企业微信 | B2B 私域、销售/客服、内部协作 | 需要企业认证、接口权限 |
| 飞书/钉钉 | 内部工具、团队协作、B2B 集成 | 企业采购、权限、上架审核 |
| 抖音/小红书 | 内容获客、种草、电商 | 平台规则、内容审核、账号风险 |
| App | 高频/深度体验、推送、离线 | 商店审核、隐私合规、获客成本 |
| Web | SaaS、工具、SEO、跨境 | 支付/备案/访问速度 |
| 线下/渠道 | 高客单、服务、行业客户 | 运营重、规模化慢 |

早期不要同时做多个入口。选一个最能验证核心价值的入口。

## 3. 合规清单

按适用情况检查：

### 基础

- ICP 备案（网站/App/小程序按平台要求）。
- 公安备案。
- 隐私政策、用户协议。
- 个人信息收集清单和同意机制。
- 账号注销、数据导出/删除。
- 未成年人保护。
- 内容审核机制。

### 数据

- 个人信息保护法（PIPL）。
- 数据安全法、网络安全法。
- 敏感个人信息（生物识别、医疗、金融、行踪、未成年人等）。
- 数据出境（如使用海外模型/云服务）。
- 数据保存期限和最小必要原则。
- 第三方 SDK 清单和共享数据说明。

### AI/内容

- 生成式 AI 服务备案/算法备案（按适用情况）。
- 生成内容标识。
- 内容安全审核。
- 训练数据/模型来源合规。
- 高风险内容的人工复核。
- 未成年人模式。

### 行业

- 金融：牌照、风控、消保、征信。
- 医疗：互联网诊疗、医疗器械、处方、隐私。
- 教育：办学许可、学科培训、未成年人。
- 电商/直播：市场主体、支付、售后、广告法。
- 招聘/人力资源：个人信息、歧视、资质。

不要把“上线后再补合规”作为默认策略。合规可能改变产品范围、数据流和商业模式。

## 4. 支付与商业化

- 微信支付、支付宝。
- 企业付款、退款、对账、发票。
- 订阅制、按量计费、服务费、一次性买断。
- 苹果 IAP（iOS 虚拟服务/订阅）。
- 小程序虚拟支付限制。
- 预售/定金/会员卡的合规和退款规则。
- 客单价、获客成本、渠道分成、毛利。

中国 B2B 常见模式：

- 项目制/服务费：适合早期高客单验证。
- SaaS 订阅：适合标准化、持续价值。
- 按量/按席位：适合团队协作和 API。
- 私有化/定制：适合大客户，但交付重。
- 渠道/代理：适合行业客户，但需要分成和培训。

## 5. AI 技术环境

- 国内模型/云服务。
- 内容安全和审核 API。
- 私有化/信创需求。
- 模型备案和供应商合规。
- 数据驻留和跨境限制。
- 成本、延迟、并发和限流。
- 国产芯片/操作系统适配（如面向政企）。

如果使用海外模型/API，先确认数据出境、网络稳定性和合规要求。

## 6. 增长与分发

- 私域：企微、社群、公众号、个人号。
- 内容：小红书、抖音、视频号、知乎、B 站。
- 搜索：百度、微信搜一搜、小红书搜索。
- 渠道/代理：行业服务商、系统集成商、协会。
- 线下：展会、沙龙、园区、行业活动。
- 应用商店/小程序搜索。
- 销售驱动：B2B 高客单、招投标、采购流程。

增长假设要和产品类型匹配。To C 内容产品和小程序工具，和 To B 私有化项目，获客方式完全不同。

## 7. 产品影响

中国市场上下文可能改变：

- 平台选择：小程序优先于 App。
- 支付和订阅设计。
- 数据架构：境内存储、权限隔离、审计。
- AI 供应商选择。
- 内容审核和人工运营。
- 获客渠道和增长循环。
- 定价和发票。
- 交付方式：SaaS、私有化、项目制。
- 合规成本和时间。

在 PRD 中明确：

- 适用地区。
- 必需资质/备案。
- 数据流和存储位置。
- 支付/发票。
- 内容审核。
- 人工运营。
- 合规风险和时间线。

## 8. 问用户的问题

- 你的第一批用户主要来自哪个平台/渠道？
- 产品是否必须在小程序/企微/飞书内使用？
- 是否涉及支付、发票、订阅或预付费？
- 是否收集个人信息、敏感数据或未成年人数据？
- 是否使用海外模型/云服务？数据是否需要出境？
- 是否需要生成式 AI 备案/算法备案？
- 是否有行业牌照或资质要求？
- 谁负责内容审核和客服？
- 你是否接受私有化/项目制交付？
- 合规预算和时间大概多少？

## 9. 常见错误

- 先做 App，后来发现用户都在微信里。
- 忽略小程序类目和支付限制。
- 用海外模型处理敏感数据。
- 没有隐私政策和账号注销。
- 生成式 AI 没有内容审核和标识。
- 把发票、退款、对账留到上线后。
- 低估备案、资质和审核时间。
- 用 To C 的增长方式做 To B 项目。
